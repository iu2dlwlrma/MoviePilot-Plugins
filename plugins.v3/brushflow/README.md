# 站点刷流

适用于 MoviePilot 3.0.0 及以上版本。每项任务绑定一个站点，工作台提供站点优先级、选种诊断、托管种子和上传统计。

## 全局统一配置

在“刷流设置”中统一选择站点、下载器、保存目录、刷新周期、选种与清理规则。站点列表从 MoviePilot 自动读取，首次默认全选，可全选、清空或手动选择；已保存的选择会完整回填。保存一次即对所选站点统一生效，不再设置单站覆盖，也不需要另点“应用到全部站点”。

站点沿用原任务 ID、下载器标签、托管种子、统计和历史。新增站点才创建任务；取消选择仅停用，再次选中继续使用原任务数据。新手考核及其优先级、独立覆盖和已经失效的旧限速字段不再使用。RSS、站点时区与既有 H&R 等兼容信息由原任务内部保留，避免改变分页来源或丢失保护标记。

存在未删除托管种子的任务须保留原下载器，处理完成后才能切换。旧配置若使用不同下载器，会保留原绑定用于管理旧种子并暂停新增，界面显示具体原因，不会把旧种子交给新的公共下载器。公共配置、站点选项读取失败时不能保存；保存失败保留草稿。 连续翻页期间保存会请求后台在安全检查点让出，最多等待 3 秒；超时不会延后提交草稿，页面保留输入供重试。分页游标、已处理候选和请求预算保持原记录。
两种模式均可在专用 Transmission 中按上传和下载余量调整后续启动名额，不超过下载器原始队列上限；下载达到限速的 85% 时不再增加名额，上传达到预算的 90% 时减少新增竞争。上传量取决于实际需求，不设最低上传量。包含非刷流任务时不接管全局队列。单站模式调整待下载队列顺序，不暂停旧种让位；降低名额不会停止已开始的任务。下载器的闲置任务豁免仍生效，实际下载数可能暂时超过队列名额。带宽仍由下载器控制。全局与任务空间上限按所有未删除种子的完整大小计算，排队任务也预留空间。相同下载器和 Hash 的记录只计一次；qBittorrent 接受任务后暂未返回 Hash 时先保留空间，待唯一标签可识别后关联。

## 站点轮转与选种

全局可选择“多站并行”或“单站驻留”。单站模式每次只给一个站新增种子。“手动重点站”可直接指定站点，清空后恢复自动调度；选种执行中也能保存，在当前页面处理后让出新增。新选择会重新检查该站连接，不受账号统计刷新退避阻挡；重复保存同一选择不会重置连接重试。顶部显示实际运行站，并注明手动选择的等待、检查、重试或暂时跳过状态。自动调度先处理分享率未达标站；全部确认达标后按配置顺序轮流驻留，默认每站 24 小时，在公共规则中统一设置。切换影响新增种子和待下载队列顺序，旧种继续下载、做种与检查，仍按原有删种条件处理。重启保留人工选择、当前站点和轮转进度。

轮到站点时使用宿主站点连通性检查，驻留中确认连接失败也进入重试。首次失败后，每隔 10 分钟重试一次，重试 5 次仍失败则跳过，选择下一站。账号刷新持续失败时使用相同重试次数与间隔。重试进度持久保存；普通失败站冷却到期不打断其他站驻留，手动重点站仍优先。当前站在后台低频刷新账号数据，失败时退避。没有合格候选不算连接故障。所有站点都不可用时等待重试，不连续轮询。

每站实际保留的已完成种子达到 50 个时停止新增，直到原删除规则清理后释放名额。同站点跨任务、下载器汇总，下载与排队任务不计入这 50 个。已有任务继续运行，后续完成可能暂时超过 50 个，不为满足数量上限强删种子。

手动重点优先于自动调度。自动站点按以下顺序选择，同级未达标站按相对目标的缺口比例排序，缺口相同时按配置顺序：

1. 账号数据有效、分享率低于目标的站点。目标默认 2，在公共规则中统一调整。
2. 分享率已达标的站点。
3. 数据未知或陈旧的站点。未知数据不视为达标，也不会挡住已确认未达标的站点。

多站并行时，到期任务使用相同优先级，每轮每项任务先添加一个符合条件的种子，再继续下一轮，直到候选用完或空间不足。单站模式只为当前站点执行这一步，其余任务等待轮到后执行。候选按需逐页读取并去重，遇到空页、重复页或空间与保种条件不允许新增时停止；RSS 读取一次订阅结果。后续页面读取失败时保留当前页及已处理记录，普通失败至少退避 60 秒；限流时同站全部刷流列表请求至少退避 10 分钟。重复调度受锁保护。站点未到刷新时间、未启用、处于运行时间段外或没有合格候选时不会强制取种；无候选不会提前换站。当前站点被停用或删除时，下一次分配选择其他启用站点。

分享率使用宿主最近的站点统计，界面显示更新时间和陈旧状态；上传、下载与分享率全为零视为未知。明确的下载量为零且上传量大于零才视为无限；上传、下载量均有效且下载量大于零时，可在分享率缺失或为零时按两者推算。缺失或非法字节数不能当作零。有效的正分享率仍可参与排序，但字节量未知时不推算下载额度。账号未达标、数据未知或陈旧时仅选择免费种子；记账下载还须确认加入后不会低于账号目标。

默认筛选做种人数 1–50、下载人数至少 1、下载人数/做种人数至少 0.1。做种人数单值表示上限，下载人数单值表示下限；两者都支持闭区间。启用人数筛选时，无法识别的人数不会视为通过。合格种子优先选择需求人数多、做种竞争低且较新的种子，需求得分每六小时衰减一半。发布时间保留原始时区，无时区时按宿主时区及站点偏移处理；启用发布时间筛选时，未知日期不会通过。还可配置免费促销、H&R 排除、标题规则、体积、发布时间和订阅排除。人数只反映抓取时的需求，不能保证后续上传量。

## 删种与保护

普通删种和动态空间清理跳过从未开始下载的任务。判断依据包括下载器明确下载状态、已完成字节、累计下载流量与持久的已开始标记，不按添加时间或排队时长推断。下载超时留空时不按累计下载时长清理；启用时只累计实际观察到的下载活动，排队、暂停与调度让位不计入。未活动清理使用配置的时长。

持续低速清理需要同时设置最低平均下载速度与观察分钟数，例如 100 KB/s、30 分钟。仅处理未完成且明确处于下载状态的种子，按连续有效采样的真实下载字节和下载时间计算平均速度。排队、暂停、校验、采样缺口和计数异常会重新建立观察基线；恢复速度或平均上传达到同一阈值时暂留并重新计时。少量上传不会永久豁免。任一设置填 0 可关闭，所有站点使用相同设置。规则同样适用于动态删种，继续遵守 H&R、共享 Hash、保护标签和文件归属检查。

启用促销清理时，免费结束前默认 10 分钟删除未完成种子及未完成文件，可统一调整提前分钟数。这个例外也适用于从未开始的排队任务；已完成种子不受此规则删除。新增候选已进入提前清理窗口时直接跳过。带时区的促销时间按真实时间换算，无时区时间按站点偏移处理。站点未提供有效结束时间时无法安排精确提前清理。

H&R 与删除保护标签仍生效；建议保留 `MOVIEPILOT,H&R`。精确到期检查与周期检查共同执行，下载器故障、保护规则或任务正在执行可能延迟删除，应给提前量留出余地。

同一 Hash 被多个站点任务管理时，须满足所有引用任务的删除规则。删除文件前会核对同一下载器的其他任务；共享文件或路径信息不完整时保留候选。该检查依据下载器报告的路径，不能识别跨下载器挂载或文件系统链接别名。删除数量和通知仅统计下载器已确认成功的操作。

部分 NexusPHP 站点普通下载地址返回 HTML 提示页；已有任务的下载提示兼容标记会保留，必要时继续追加 `letdown=1`。有效登录信息仍是下载前提。

## 上传统计

工作台按下载器累计上传、下载字节的真实增量统计最近约 30 分钟表现，并显示实际窗口时长、下载、排队和做种数量。采样中断或数据不完整时会标记，不能把短窗口折算或瞬时速度当作完整小时上传量。站点账号记账可能滞后于下载器，也可能受促销倍率影响，两者分别展示。

翻页选种期间继续采样，并按任务原检查周期执行清理，下载器状态与空间占用随采样刷新。

运行诊断分别展示账号统计刷新和下载器种子检查，并区分账号流量未解析、登录状态未识别和请求失败。账号刷新失败显示连续次数、最近尝试和下次重试时间，不代表站点不通或种子检查失败。宿主已识别用户但流量缺失时，可从同站已登录首页的明确统计栏补读并存入插件缓存；无法确认的值仍为未知，下载显示为零时需有明确无限标记才认定无限分享率。没有真实刷流报告时不显示默认选种流水线。设置菜单打开时仍刷新运行状态，保留尚未保存的设置草稿。

## 仓库与安装

个人版本为 `OriechoBrushFlow` 7.3.2，显示名称仍为“站点刷流”。源码位于 `plugins.v3/brushflow`，市场清单位于根目录 `package.v3.json`。发布包保留 `brushflow/` 顶层目录及 `dist` 前端产物。

将本仓库作为插件市场来源安装个人版本。源码目录采用 `brushflow/`；内部 ID、API、前端模块和配置前缀继续沿用 `OriechoBrushFlow` / `oriechobrushflow_`，目录调整不迁移运行数据。其内部 ID、API、前端模块和配置命名空间与上游 `BrushFlow` 分开；旧任务配置、任务 ID、托管记录和站点请求预算需要按受控迁移流程转入新插件命名空间。托管标签 `刷流-*`、任务数据键格式与业务事件名保留。迁移期间避免两个插件同时管理相同任务；安装本包不会自动复制或删除旧数据。

## 开发与验证

在具有宿主依赖 Pydantic 2 的 Python 环境中，于仓库根目录执行 `python -m unittest discover -s tests -v`。测试隔离宿主入口，不连接实际数据库、站点或下载器。

前端使用 Vue、Vuetify 与 Vite 依赖，在插件目录执行 `npm ci`、`npm run build`，产物位于 `dist/assets`。后端插件版本与市场清单版本保持一致。发布需在 GitHub Actions 手动运行主分支的 `Plugin Release` 工作流，通过测试后按市场清单打包；仓库重置后须先重新发布正式发行包，才能从本仓库安装或更新。
